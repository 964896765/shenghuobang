# V4 Discover / Mall / Publish Redesign

## 1. 背景与目标

- 本轮改版在独立分支 `codex/v4-discover-mall-publish-redesign` 上进行，不修改 `main`，不与稳定化 PR #9 混改。
- 目标不是在现有首页堆叠结构上继续修补，而是重建 V4 的信息架构、一级导航和核心内容浏览体验。
- 改版遵循“发现优先、交易独立、发布统一、我的收束、位置唯一入口、产品护照入口收敛”的产品决策。

## 2. 取消首页的原因

- 当前首页承担了过多职责：城市定位、搜索、问 AI、相机、八宫格入口、附近服务、工作台、内容流，信息噪音过大。
- 首页的“头部能力 + 功能宫格 + 大卡堆叠”结构缺少单一目标，不利于形成稳定的内容消费路径。
- 首页内容和发现页职责交叉，导致公开内容发现、业务入口分发、角色工作台同时争抢首屏。
- 当前首页的工作台、商城、需求、产品追溯等入口分散，造成“我该看内容、逛商品还是发东西”不清晰。
- 最终方案是彻底取消首页，不保留空壳首页，也不把首页整体改名为“广场”或“发现”。

## 4. 发现页职责

发现页是整个 App 的公开内容发现中心，负责：

- 查看公开内容
- 查看需求和协作机会
- 查看创意和项目进度
- 查看经验、案例和视频
- 查看公开商品内容
- 查看公开服务内容
- 关注作者、项目和主题
- 点赞、评论、收藏、分享

发现页不负责：

- 购物车
- 下单与支付
- 售后
- 私人订单
- 私人协作任务
- 精确地址
- 未发布草稿
- 内部项目记录

### 发现页固定头部

固定结构：

- 当前城市
- 搜索 / 问 AI
- 相机

规则：

- 头部吸顶
- 城市点击进入“位置与隐私”
- 搜索支持内容 / 需求 / 商品 / 服务 / 问 AI
- 相机入口提供拍照搜索、扫描产品护照、拍摄并发布
- 全 App 唯一主动定位入口放在发现页左上角

商城顶部结构：

商城频道：

- 推荐
- 闲置

## 16. 频道纵向拉伸问题的当前分析

当前基线文件 [discover.tsx](file:///c:/dev/shenghuobang-rc12a/app/(tabs)/discover.tsx) 中，频道栏使用横向 `ScrollView` 和 `Pressable` 胶囊按钮，当前尚未写死固定高度，也没有单独的频道组件与骨架层隔离。

当前风险点：

- 页面主体外层存在 `flex-1` 容器
- 频道项没有固定高度约束
- 频道栏与内容状态切换共存在同一页面体内
- 后续若把 loading/empty/error 包裹进错误的父容器，容易把频道按钮一起带入拉伸布局
- 当前发现页仍使用整体 `LoadingView` / `ErrorState` / `EmptyState` 切换，频道栏与内容区边界不够清晰

本轮结论：

- 纵向拉伸的真实高风险源是“频道栏与内容区未做稳定布局隔离”，而不是业务数据本身
- 编码阶段必须把频道栏抽成独立吸顶区域，并为 tab item 设置固定高度与自适应宽度，禁止 `flex: 1 / flexGrow / stretch`
